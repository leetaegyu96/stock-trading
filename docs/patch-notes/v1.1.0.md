# v1.1.0 — 2026-07-08

**서브프로젝트 2: 라이브 모드 (KIS 실시세 + 스케줄러 + PostgreSQL 영속).**

완료된 순수 매매 엔진(v1.0.0)을 실시간으로 구동한다. KIS 오픈API에서 실시세를 받아
스케줄러가 엔진을 돌리고, 상태·이력을 PostgreSQL에 영속화하여 재시작에도 이어서 매매한다.
순수 엔진 코드(engine/portfolio/signals/…)는 한 줄도 변경하지 않았다(기존 63 테스트 무손상).

## 하이라이트

- **KIS는 데이터 피드 전용** — 주문하지 않고, 3캐릭터는 엔진이 자체 시뮬레이션.
- **라이브 = 실시간으로 이어지는 리플레이** — orchestrator가 `run_replay`와 동일한 엔진
  메서드를 같은 순서로 호출. 동치성 테스트로 보증.
- **재시작 복구** — DB에서 상태 복원(rehydrate) + 꺼져 있던 거래일은 확정 일봉으로 재생(갭 리플레이).

## Added — `simcore/live/`

| 모듈 | 역할 |
|------|------|
| `settings.py` | pydantic-settings 설정 로더(시크릿 마스킹) |
| `ratelimit.py` | 토큰버킷 레이트리미터 |
| `kis_client.py` | KIS REST(토큰 캐시·현재가·일봉·시총랭킹·해외시세), 백오프·401 재발급 |
| `calendar.py` | KR/US 거래일·세션시각(zoneinfo, DST 자동) |
| `db.py` | SQLAlchemy ORM 13테이블(스펙 §5) |
| `repository.py` | 상태 persist/rehydrate, 이력 append, run_state 멱등, flow 큐, 단일 트랜잭션 |
| `orchestrator.py` | on_close(신호→evaluate_close)·on_open(체결+입출금)·on_tick(5분 손익절) |
| `recovery.py` | 갭 리플레이 재시작 복구 |
| `scheduler.py` | APScheduler 배선 + 거래일 가드 |
| `__main__.py` | 데몬 진입점 + `run`/`deposit`/`withdraw` CLI |

- **유니버스**: KR = KIS 시가총액 상위 top-N, US = Wikipedia S&P500(기존).
- **DB**: PostgreSQL. 상태(현금·포지션·pending·쿨다운)와 이력(거래·입출금·자산곡선·일봉캐시·유니버스)을 영속.
- **신규 의존성**: httpx, SQLAlchemy 2.x, psycopg, APScheduler, pydantic-settings.

## Fixed (구현 중 코드리뷰가 발견·수정)

1. **재시작 후 거래 유실** — `append_new_trades`가 DB 저장 건수 기준이라 rehydrate 후
   in-memory 거래목록이 비면 신규 거래가 영영 기록되지 않던 버그. 세션 로컬 커서로 수정.
2. **cross-market stale 평가** — 범용형의 반대 시장 보유분이 평단가(원가)로 평가되어
   equity_curve/TWR가 오염되던 버그. `_last_price` 인스턴스 캐시로 최근가 평가.
3. **마감 사이클 비원자성** — 5개 저장이 독립 트랜잭션이라 크래시 시 evaluate_close가
   재실행되어 쿨다운이 이중 차감되던 버그. 단일 트랜잭션으로 수정(스펙 §144).
