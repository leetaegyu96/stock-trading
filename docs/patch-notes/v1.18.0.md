# v1.18.0 — 2026-09-02

범용형의 왕복 환전 제거. 사후분석 리포트 처방 중 **현재 운영 구성에서 유효한 마지막 항목**이다.

## 배경 — 왜 이것만 남았나

`docs/reviews/2026-09-02-live-loss-autopsy.html` 의 처방 중 나머지(추세 적신호 동어반복 통합, G13↔R13 축 분리, 부분매도 연쇄 제한)는 전부 **점수 매도**에서 비롯된 문제인데, v1.16.0에서 `SIGNAL_SELL_ENABLED=false` 로 그 경로를 껐으므로 현재 구성에서는 **작동하지 않는다**. 반면 환전 왕복은 손절·트레일링 매도에서도 계속 발생하므로 유일하게 살아 있는 누수였다.

## Fixed

**US 매도마다 달러 전액을 원화로 되돌리던 왕복 환전** (PR #68)

`Engine._sell` 이 범용형의 US 매도마다 `convert_all_usd_to_krw` 를 호출하고, 다음 US 매수에서 `convert_to_usd` 로 되돌려 **왕복 0.2%**(편도 0.1% × 2)를 물었다. 라이브 6주에 약 160만원(범용형 손실 1,174만원의 14%), 3.2년 리플레이 총 회전액 기준 초기자본의 5.0%p 규모.

근본 원인은 매수 예산을 `pf.cash[KRW] / slots` 로만 계산한 데 있다 — 달러를 보유하면 여력이 과소평가되므로 전액을 원화로 되돌릴 수밖에 없는 구조였다.

- `Portfolio.buying_power(cur, fx)` — **양 통화 합산** 매수 여력
- `Portfolio.convert_to_krw` · `ensure_cash` — 부족분만 환전
- `Engine._sell` 자동 전액 환전 제거, `_buy` 는 보유 통화를 먼저 쓰고 부족분만 환전
- `Portfolio.withdraw` — 원화 부족 시 부족분을 달러에서 메움. **회귀 방지**: 왕복을 없애면 달러를 보유하게 되므로, 이게 없으면 총자산이 충분해도 원화 출금이 실패한다
- `convert_all_usd_to_krw` 는 청산·명시적 전량 환전용으로 유지

**`tests/live/test_settings.py::test_defaults_and_base_url` 격리** — pydantic-settings 가 리포 루트의 실제 `.env`(운영 `KIS_ENV=paper`)를 읽어 기본값 검증이 환경에 따라 깨졌다. `_env_file=None` 로 차단. 이 세션 내내 유일하게 빨간 테스트였다.

## 검증

같은 유니버스에서 **범용형만** 변한다:

| 구간 / 규칙 | 수정 전 | 수정 후 |
|---|---|---|
| 3.2년 · 현행 규칙 | −5.4% / MDD −41.3% | **+2.7%** / MDD −37.7% |
| 3.2년 · 현재 운영구성 | +89.0% / MDD −15.3% | **+90.2%** / MDD −15.2% |
| 2026년 8개월 · 현재 운영구성 | +17.1% / MDD −9.3% | **+18.1%** / MDD −9.2% |

**대조군**: 국내형(+159.9% / MDD −17.1%)·해외형(+58.7% / MDD −13.9%)은 단일 통화라 소수점까지 불변 — 변경 범위가 정확함을 확인했다.

회수액이 5.0%p 추정보다 작은 것은 시장 간 **순이동분은 어차피 환전해야 하고 왕복 중복분만** 사라지기 때문이다.

테스트 20건 추가. 전체 **468 passed, 실패 0** — 이 세션에서 스위트가 완전히 초록이 된 첫 버전.
