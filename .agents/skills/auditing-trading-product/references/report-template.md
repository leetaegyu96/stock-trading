# Claude 전달용 감사 보고서 형식

```markdown
# YYYY-MM-DD 트레이딩 제품 감사

## 판정
GO | CONDITIONAL | RED

- 현재 제품 모드:
- 확인한 브랜치/커밋:
- Chrome 관찰: URL, KST 시각, 뷰포트
- 실행한 검증:
- 미검증 범위:

## 핵심 결론
- 가장 중요한 사실 3개
- 실전 전환 가능 여부와 이유

## 유지할 강점
- 변경 중 보존해야 할 코드·제품 특성

## 발견 사항
### [P0|P1|P2] 제목
- 영역: 코드 | 데이터 | 신호 | 성과 | 안전 | UI/UX | 접근성 | 복기
- 근거: 파일:줄, 화면 URL, 재현 단계, 수치
- 실제 결과:
- 기대 결과:
- 사용자/자금 영향:
- Claude 수정 지시:
- 완료 조건:
- 재검증:

## 16:9 화면 평가
- 1366×768 / 1920×1080 / 2560×1440
- 공간 사용률, 첫 화면 정보, 스크롤/겹침, 확대 결과

## 종목별 매매 복기 평가
- 집계 정확성, 포지션 생애, 차트·마커·타임라인
- 초보자 설명, 반대 근거, 필터·성능·접근성

## 청신호·적신호 균형
- 독립 정보와 중복 파생
- 게이트·강제결정 정합성
- 포지션 사이징·손절·집중 위험
- 미구현/미수집 축

## 성과 신뢰성과 실전 경계
- 벤치마크·비용·holdout
- 데이터 편향과 과적합
- 현재 paper/shadow 범위
- 향후 real-order 진입 조건

## Claude 작업 순서
1. P0 데이터·행동 정합성
2. P1 의사결정·복기 UX
3. P1 전략 검증·외부 정보축
4. P2 시각 완성도

## 재검증 체크리스트
- 명령과 기대 결과
- Chrome 경로와 과업
- 수정됨/부분 수정/회귀/미검증 표
```

## 우선순위

- P0: 돈, 행동, 데이터 의미, 보안 또는 사용자 오판을 직접 유발
- P1: 핵심 의사결정, 복기, 검증 또는 운영을 현저히 방해
- P2: 완성도, 효율, 일관성, 접근성 개선

해결되지 않은 P0가 하나라도 있거나 핵심 증거가 미검증이면 `GO`를 사용하지 않는다.
