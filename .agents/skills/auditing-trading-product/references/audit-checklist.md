# 통합 감사 체크리스트

감사마다 끝까지 읽고 각 영역을 `확인 / 문제 / 미검증 / 해당 없음`으로 판정한다.

## 범위와 증거

- 현재 브랜치, 최근 변경, 사용자 소유 미커밋 변경을 확인한다.
- 제품 모드가 replay, paper/shadow, real-order 중 무엇인지 코드로 확인한다.
- 화면 관찰에는 URL, KST 시각, 뷰포트, 데이터 기준시각을 기록한다.
- 코드 주장은 파일과 함수, 화면 주장은 재현 단계나 캡처로 뒷받침한다.
- 실행환경이 막히면 원인과 미검증 범위를 분리한다.

## 코드와 데이터 흐름

- 신호 → 점수/게이트 → 엔진 결정 → 주문/체결 모델 → DB → API → UI를 추적한다.
- 부분매도, 전량매도, R18, R5+R23, R7, R10 등 모든 강제청산의 행동과 문구가 일치하는지 확인한다.
- 통화, 환율, 세금, 수수료, 수량, 가격, 손익 부호와 단위를 대조한다.
- 총자산, 현금, 평가액, 자산곡선 마지막 값의 산술 정합성을 확인한다.
- 로딩, 빈 데이터, 일부 결측, 지연 시세, API 오류, WebSocket 단절을 확인한다.
- 전략·파라미터·데이터 버전과 결정 ID가 재현 가능한지 확인한다.

## 청신호·적신호와 리스크

- 구현 신호와 항상 꺼진 스텁을 구분한다.
- OHLCV 파생 신호들이 독립 증거처럼 중복 가중되는지 확인한다.
- 카테고리 상한과 매수 게이트가 실제 의도대로 작동하는지 확인한다.
- ADX 방향성, 저거래량 상승, 돌파 추격 등 맥락 의존 신호를 점검한다.
- 고정 손절과 ATR/변동성 기반 손절을 비교할 근거가 있는지 확인한다.
- 종목, 업종, 시장, 상관관계, 거래당 위험 예산과 현금비중을 확인한다.
- 처리 순서가 자산배분 결정을 대신하지 않는지 확인한다.
- 신호별 ablation, 파라미터 안정성, 다중 탐색 과적합을 확인한다.

## 성과 신뢰성

- 전략과 같은 기간·통화·비용의 벤치마크를 비교한다.
- TWR, MDD와 함께 CAGR, 변동성, Sharpe/Sortino, Calmar, Profit Factor, 기대값, 평균 손익비, 연속손실, 회복기간을 확인한다.
- 튜닝 구간, walk-forward, 완전 미사용 holdout을 구분한다.
- point-in-time universe, 상장폐지, 분할, 배당, 수정주가, 휴장일을 확인한다.
- 슬리피지, 스프레드, 시장충격, 미체결·부분체결, 비용 2~5배 스트레스를 확인한다.
- 1억원 결과를 100만원에 그대로 적용하지 않는다. 정수주, 최소비용, 환전, 집중도를 재검증한다.
- 상승·하락·횡보, 급락·갭, 데이터 장애 구간별 성과를 확인한다.

## 16:9와 프리미엄 UI/UX

필수 뷰포트: 1366×768, 1440×810, 1920×1080, 2560×1440. 변경 영향이 있으면 125%, 150%, 200% 확대도 확인한다.

- 콘텐츠 최대폭과 실제 사용률을 측정한다. 1920px에서 좁은 중앙 섬처럼 보이지 않아야 한다.
- 첫 화면에서 운영 모드, 데이터 신선도, 오늘의 행동·위험, 포트폴리오 상태가 우선 보이는지 확인한다.
- 카드·패널 시작선, 숫자 정렬, 테이블 열 너비, 가로 스크롤, 긴 종목명을 확인한다.
- 선택 기간 수익률과 전체 TWR, 실현손익과 미실현손익을 분리한다.
- 색만으로 매수/매도·이익/손실을 전달하지 않는다.
- 대비, 키보드 순서, 포커스, `aria-pressed`, 정렬 상태, reduced motion을 확인한다.
- 장식보다 정보 위계, 한 화면의 판단 완결성, 오류 복구를 평가한다.

## 종목별 매매 복기

- 종목별 매수 횟수, 매도 횟수, 완결 포지션 수를 구분한다.
- 실현손익, 현재 보유손익, 거래비용, 종합손익과 계산 기준을 표시한다.
- 수익률은 단순 체결가 평균 비율로 왜곡하지 말고 자금가중 방식과 포지션 단위 수익률을 명시한다.
- 진입, 추가매수, 부분매도, 최종청산을 하나의 포지션 생애로 묶는다.
- 가격 차트에 매수·매도 마커, 평균매입가, 손절선, 트레일링선, 보유 구간을 표시한다.
- 차트 마커와 거래 타임라인 선택이 양방향 동기화되는지 확인한다.
- 체결가, 수량, 신호, 결정 유형, 수수료, 보유기간, 실현손익을 확인할 수 있어야 한다.
- `왜 진입 / 반대 근거 / 왜 청산 / 결과 / 다음에 바꿀 점`을 한 흐름에서 제공한다.
- 자동 생성 사실과 사용자 복기 노트를 시각적으로 분리한다.
- 종목·기간·결정 유형·손익 필터가 URL과 뒤로가기에 보존되는지 확인한다.
- 100건과 1,000건에서 페이지네이션 또는 가상화와 반응성을 확인한다.

## 실전 전환 경계

현재 저장소가 시세연동 paper/shadow라면 이를 정확히 표시한다. 사용자가 별도로 real-order 단계를 승인할 때만 아래를 진입 조건으로 평가한다.

- 별도 키, DB, 배포환경과 명확한 PAPER/SHADOW/LIVE 배너
- 일·주 손실, MDD, 주문금액, 종목·업종·시장 노출 한도
- 전역·전략별 kill switch와 매수 중지
- stale data, clock drift, 달력 오류, API 장애의 fail-closed 동작
- 주문 idempotency, 접수·거부·부분체결·정정·취소 상태 모델
- 브로커 체결·잔고 reconciliation과 불일치 경보
- 감사로그, 비밀관리, 최소권한, 백업·복구 훈련
- paper 4~8주 → shadow 4주 → 수동승인 소액 → 제한적 자동화 승격

## 재검증

- 원래 증거와 같은 URL, 뷰포트, 데이터 조건으로 비교한다.
- 자동 테스트, 빌드, 관련 API, Chrome 흐름을 다시 실행한다.
- `수정됨 / 부분 수정 / 회귀 / 미검증`을 구분한다.
- 새 디자인이 데이터 의미나 안전 경고를 숨기지 않았는지 확인한다.
