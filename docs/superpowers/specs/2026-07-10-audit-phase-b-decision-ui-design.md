- 날짜: 2026-07-10
- 상태: 자율 확정([[autonomy-full-pipeline]] — 사용자 검토 게이트 생략, self-review로 대체)
- 요구사항 원본: `docs/reviews/2026-07-10-trading-product-audit.md` §4(P1 5건), §6 2단계. finding 인용, 문구 복제 안 함. 각 P1의 취지가 인수 기준.
- 상위: Phase A(v1.8.0, P0 신뢰회복) 후속. 목표: 첫 화면을 "사후 성과판"에서 **"오늘의 의사결정판"**으로 — 사용자가 "지금 무슨 일이 벌어지고 왜 다음 행동을 해야 하는지" 알 수 있게.

## 범위 밖 (명시 — 데이터/단계 부재)

- 업종·실적발표일·주요 이벤트(§4 보유종목 항목 일부): 데이터 소스 없음 → 4단계(외부 정보축)로.
- 시장 국면 심층·주요 이슈(의사결정판 5번 항목): 뉴스/거시 파이프라인 없음 → 지수 vs SMA 요약 수준만.
- 신호 재설계·리스크 예산(§3): 별도 서브프로젝트.
- 접근성·모바일 카드형(§4 접근성): 색+아이콘 병행 등 저비용 항목만 포함, 모바일 전면 개편은 후속.
- CSV 내보내기(리포트가 명시적으로 후순위 지정).

## 1. P1-A — 첫 화면 "오늘의 의사결정판" 재구성

메인 상단을 리포트 권장 순서로 재배열:
1. **운영 상태 밴드**(기존 ModeBar 확장): PAPER·시장별 데이터 기준·연결.
2. **오늘의 행동**: 대기 매수/매도 주문(pending_orders — 결정유형·트리거 포함), 최근 강제매도 경보(최신 거래일 FORCED_SELL), 행동 없으면 "오늘 예정된 행동 없음" 명시.
3. **포트폴리오 위험**: 캐릭터별 현금비중·총 노출·종목 집중도(최대 보유 비중)·일 손익. (업종 집중은 범위외 — 종목 집중으로 대체하고 라벨 정직하게.)
4. **성과 vs 벤치마크**(Phase A 데이터 재사용 — 캐릭터 카드가 이미 표시, 배치만 상향).
5. 시장 요약(지수 종가·등락, MarketMovers 재배치) / 6. 캐릭터 비교·최근 체결(기존 유지, 하단).

## 2. P1-B — 신호를 "현재 상태"와 "과거 체결"로 분리

**데이터 기반**: 마감 시점 상태를 영속하는 `SignalStatusRow` 신설(리플레이 마지막 거래일 시드 + 라이브 on_close 갱신):
- **후보 상태**(캐릭터×종목): green_score·red_score·buy_gate·status(예약/차단)·**block_reason**(점수부족/게이트미충족/보유중/쿨다운/슬롯부족/현금부족)·as-of 날짜.
- 엔진 확장: `evaluate_close`가 매수 후보 평가 결과(통과/차단+사유)를 반환·기록(기존 결정 로직 무변경 — 관찰만 추가). fill_open의 슬롯/현금/가격 차단도 사유로 기록.
- 화면: **"오늘의 후보"** 테이블(종목·행동·점수·게이트·차단 사유="왜 아직 안 샀나") — 상세 페이지 신설 섹션 또는 메인 "오늘의 행동" 하위.
- **"왜 보유 중인가"**: 보유 종목의 현재 red_score·손절선·트레일선·최고가·다음 행동 조건(부분매도/전량매도 임계까지 남은 점수) — P1-C와 통합.
- **"왜 팔았나"**: Phase A 결정 표시로 이미 충족(결정유형·트리거·체결) — 거래내역에서 확인. 이후 가격 변화는 범위외.

## 3. P1-C — 보유종목 리스크 정보

PositionsTable(및 API positions)에 추가:
- 포트폴리오 비중(평가액/총자산), 진입 사유(BUY trade의 trigger_rule="게이트+N점" 역참조), 현재 기술적 신호 점수(SignalStatusRow), **손절 가격·트레일링 가격·손절까지 거리(%)·잠재 손실액**(수량×(현재가−손절가)), 시세 기준시각, 매도 대기 상태(pending_sells).
- 업종·실적일은 범위외(§0) — 컬럼 자체를 만들지 않음(빈 컬럼 금지).

## 4. P1-D — 거래내역 페이지네이션·필터·포지션 생애

- 기본 20건 + 페이지네이션(백엔드 offset/limit — queries.trades에 이미 limit 존재, offset 추가).
- 필터: 기간·종목·매수/매도·결정 유형(백엔드 쿼리 파라미터).
- **포지션 생애 복기**: 같은 종목의 진입→부분매도→청산을 하나의 묶음으로 그룹 표시(BUY에서 시작해 보유수량 0이 되는 SELL까지 — 서버측 그룹핑, 생애 단위 손익 합계).
- 행은 핵심만 + 기존 펼침 유지.

## 5. P1-E — 지표 설명·기간 명시

- TWR 툴팁("입출금 영향을 제거한 수익률"), 자산곡선 구간 수익률에 "선택 기간 수익률" 라벨(전체 TWR과 구분), 승률 옆 평균이익·평균손실·손익비(risk_metrics 재사용 — 이미 API에 있음, 배치만).
- 색+아이콘/부호 병행(상승▲/하락▼) — 접근성 저비용 항목.

## 6. 아키텍처

- 신설: `SignalStatusRow`(db) + 엔진 후보 관찰 훅(결정 로직 무변경 원칙 — Phase A의 "관찰≠행동" 경계 유지) + 시드/라이브 기록 + queries/스키마/API + 프론트 신규 섹션.
- 파일 영향: `engine.py`(후보 평가 기록 반환), `replay.py`(마지막 날 상태 수집), `live/orchestrator.py`(on_close 기록), `live/db.py`·`repository.py`, `seed_from_replay.py`, `dashboard/backend`(queries·schemas·app·summary), 프론트(Main 재구성·CandidatesTable 신설·PositionsTable 확장·TradesTable 페이지네이션·MetricsPanel 라벨).
