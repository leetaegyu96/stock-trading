# 장중 자동매매 루프 (Intraday Trading Loop) — 설계 스펙

> 작성 2026-07-20. 24시간 라이브 페이퍼 서버에서 장중 여러 번 자동 매수·매도해 잔고 성장 가능성을 관측한다.
> 근거: 감사 리포트 `docs/reviews/2026-07-10-trading-product-audit.md`, 다음 할 일 `docs/next-steps.md`.

## 목적 / 배경

- 현재 매매는 **하루 1사이클**이다: 마감(`on_close` 16:10)에 일봉으로 매수 후보·매도를 정해 대기열에 넣고, 다음 개장(`on_open`)에 체결한다. 5분 틱(`on_tick`)은 보유 종목의 **손절·트레일 스톱만** 한다.
- 사용자는 **장중 기회 포착**을 원한다: 마감까지 안 기다리고, 장중에 매수 신호가 뜨면 그날 바로 사고, 조건이 무너지면 판다. 하루에도 종목당 몇 번씩.
- 운영 형태는 **24시간 라이브 페이퍼 서버**(모의 자금, KIS는 시세 조회 전용, 실주문 없음). 리플레이/백테스트는 테스트 수단일 뿐이며, 이 기능의 목표가 아니다.

## 범위 (이번 스펙)

포함:
1. 장중 10분 주기 자동매매 실행 루프 (매수·매도·손절 전부).
2. 기존 신호 배터리 재사용(MA·RSI·MACD·볼린저·스토캐스틱·ATR·ADX/DI·OBV·VWAP·SAR·일목 → green/red 게이트).
3. 신규 지표 2종(OHLCV만, 일봉·장중 공용): **가격괴리율**, **지지/저항선**.
4. **체결강도**(실시간 호가 기반 게이팅, KR 적용 / US 미지원 스킵).
5. 휩쏘 방지·킬스위치·대시보드 구분 표시.

**제외(별도 후속)**:
- 뉴스·토픽·이슈 흐름 등 외부 정보축 → 감사 4단계, 별도 프로젝트. 감사 지침상 뉴스는 자동주문을 직접 트리거하지 않는다.
- 분봉 자체 신호 체계(5분봉 OHLCV 지표) → 이번엔 일봉 신호를 장중 재평가하는 방식이며, 분봉 신호 신설은 범위 밖.
- 인트라데이 백테스트/리플레이 등가성 → 다루지 않음(아래 §비목표).

## 비목표 (Non-goals)

- 리플레이-라이브 등가성을 인트라데이까지 확장하지 않는다. 인트라데이 ON이면 라이브가 리플레이와 갈라진다는 사실만 **정직하게 문서화**하고, 기존 등가성 테스트는 플래그 OFF 경로로 보존한다.
- 실주문(실전 매매)은 넣지 않는다. PAPER 모드 유지.

## 핵심 원칙

- **플래그 격리**: `intraday_enabled`(기본 OFF). OFF면 현재 동작·전체 pytest·리플레이 등가성이 **100% 불변**. 운영 서버만 ON.
- **기존 자산 재사용**: 신호 평가는 `signals.evaluate_frame` + `engine.evaluate_close`의 매수/매도 판정 로직을 그대로 쓴다. 새 지표는 evaluate_frame에 컬럼으로 추가돼 **일봉·장중 공용**.
- **비용 정직성**: 장중 체결도 기존 `costs`(수수료·세금·FX 수수료·슬리피지)를 그대로 적용 — "잔고가 진짜 늘 수 있나"를 공정하게 관측.
- **부분 실패는 스킵**: 시세/호가 조회 실패 종목은 이번 틱 스킵·다음 틱 재시도(현행 패턴). 데이터 없는 조건(US 체결강도)은 해당 조건만 건너뛰고 나머지 신호로 판단.

## 아키텍처 & 데이터 흐름

### 컴포넌트 경계

- **`LiveScheduler`** (`simcore/live/scheduler.py`) — 장중 스캔 틱을 10분 주기로, **장 시간 중에만** 발화하도록 시간 가드 추가. `intraday_enabled`가 켜져 있을 때만 인트라데이 경로 호출.
- **`Orchestrator.on_intraday(d, market, universe)`** (`simcore/live/orchestrator.py`) — 신규. 유니버스 현재가+당일 누적거래량(+KR 체결강도) 수집 → 종목별 잠정 일봉 프레임 구성 → 엔진 장중 평가 호출 → 트랜잭션으로 상태·거래 영속. 기존 `on_tick`(손절 전용)은 유지하거나 이 경로에 흡수.
- **`Engine.evaluate_intraday(d, market, frames, strengths, fx)`** (`simcore/engine.py`) — 신규. 잠정 프레임으로 매수/매도 판정을 재사용하되 **즉시 현재가 체결**(대기열 경유 안 함). 휩쏘 캡·장중 쿨다운·킬스위치 적용.
- **`indicators`** — 신규 함수 `disparity`(괴리율), `support_resistance`(스윙 고저/피벗). `signals.evaluate_frame`에 컬럼 추가.
- **`KisClient.execution_strength(market, symbol)`** (`simcore/live/kis_client.py`) — 신규. KR 호가/체결 API로 체결강도 조회. US는 미지원 → `None` 반환.

### 잠정 일봉(provisional bar) 구성

각 종목마다: 확정된 과거 일봉 히스토리(어제까지) + 오늘 형성 중인 봉 1개를 append.
- 시가 = 오늘 첫 관측가(없으면 전일 종가)
- 고가 = 당일 관측 최고, 저가 = 당일 관측 최저 (틱마다 갱신)
- 종가 = 현재가
- 거래량 = 현재가 조회 응답의 당일 누적거래량(`acml_vol`) — 근사 대신 실제 당일량
이 프레임에 `evaluate_frame`을 돌리면 RSI/MACD/일목/괴리율 등이 현재가 기준으로 산출된다. 종가가 장중 움직이면 지표도 갱신된다.

### 체결강도 게이팅

- 과거 히스토리가 없는 실시간 전용 값 → evaluate_frame 컬럼이 아니라 **장중 판정의 오버레이**로 처리.
- 매수: 신호 게이트 통과 + 체결강도 ≥ 임계(매수 우위)일 때만 실제 매수.
- 매도: 체결강도 급락은 매도 판정에 가점(보조).
- US 등 체결강도 `None`이면 이 조건을 **무시**(통과 취급)하고 기존 신호만으로 판단.

## 상세 규칙

### 매매 판정(장중)
1. 유니버스 각 종목의 잠정 프레임 평가 → green/red·게이트 산출(기존 로직).
2. **매수**: 미보유 & 게이트 통과 & (체결강도 조건 충족 or 데이터 없음) & 슬롯 여유 & 현금 충분 & 휩쏘/쿨다운 통과 → 현재가 즉시 매수(비용 적용).
3. **매도**: 보유 & 매도 규칙 발동(기존 R-rule) → 현재가 즉시 매도. 손절·트레일은 현행 `check_stops` 유지.

### 휩쏘 방지 (중간 공격성)
- 종목·캐릭터·당일 기준 **매수 ≤ 3회, 매도 ≤ 3회**. 손절/트레일/강제청산은 이 카운트에서 **예외**.
- 매도 후 **재매수 장중 쿨다운 30분**(신규 파라미터 `intraday_reentry_cooldown_min`). 장중에는 기존 `cooldown_days`(2일) 대신 이 값을 적용.
- 일일 카운트·마지막 매도 시각은 상태에 보관, 개장/일자 변경 시 리셋.

### 킬스위치
- 캐릭터별 **당일 손익률 ≤ −5%** 도달 시 그날 **신규 매수 중단**(신규 파라미터 `intraday_daily_loss_halt_pct = -0.05`).
- 손절·트레일·매도 규칙은 계속 동작(리스크 축소는 막지 않음). 다음 거래일 자동 해제.

### 신규 지표
- **가격괴리율** `disparity(close, period)` = (close − SMA(period)) / SMA(period). 기본 기간은 config로.
- **지지/저항선** `support_resistance(high, low, close, lookback)` = 최근 스윙 고저 또는 피벗 기반 근접 지지·저항 레벨. 매수는 지지 근접·저항 돌파, 매도는 저항 거부 등 규칙에 반영(구체 규칙은 config 점수화로, 기존 green/red 카테고리에 편입).

## 설정 (config)

신규 필드(기본값은 OFF/보수):
- `intraday_enabled: bool = False`
- `intraday_scan_minutes: int = 10`
- `intraday_max_buys_per_symbol: int = 3`
- `intraday_max_sells_per_symbol: int = 3`
- `intraday_reentry_cooldown_min: int = 30`
- `intraday_daily_loss_halt_pct: float = -0.05`
- 체결강도 임계·괴리율 기간·지지저항 lookback 등 지표 파라미터.

## 오류 처리 / 안전

- 현재가·체결강도 조회 실패 → 해당 종목 이번 틱 스킵, 다음 틱 재시도(로그).
- 장 시간 외 스캔 방지(시간 가드). 휴장일 가드는 현행 유지.
- 플래그 OFF 시 신규 경로 진입 안 함(기존과 동일 보장).
- KIS 레이트리밋(10/초)로 60종목 스캔 시 약 6초 — 여유. 초과 시 리미터가 자연 조절.

## 대시보드 / 기록

- 장중 체결은 `DecisionType`/trigger에 **`INTRADAY_BUY`/`INTRADAY_SELL`** 태그를 부여해 거래내역·"오늘의 행동"에서 일봉 사이클 거래와 구분.
- 보유/후보 화면에 체결강도·괴리율·지지저항 노출(가능 시). trading-rules 문서에 장중 규칙 절 추가.

## 테스트 전략

- **회귀(최우선)**: `intraday_enabled=False`면 기존 엔진·리플레이·동치성·전체 pytest가 **무수정 통과**(플래그 OFF 경로 불변 증명).
- 잠정봉 구성(누적거래량 반영) 단위 테스트.
- 장중 매수/매도 체결(현재가·비용 적용) 테스트.
- 휩쏘 캡(3회 초과 차단)·재매수 쿨다운(30분)·손절 예외 테스트.
- 킬스위치(−5% 도달 시 신규 매수 중단, 매도 계속) 테스트.
- 신규 지표 `disparity`·`support_resistance` 수치 단위 테스트.
- 체결강도 게이팅: KR 값 있을 때 필터 동작 / US `None`이면 스킵(기존 신호로 통과) 테스트.
- KIS 클라이언트 체결강도 파싱은 응답 픽스처로 테스트(실호출 아님).

## 마이그레이션 / 배포

- config 신규 필드는 기본값이 있어 하위호환. 스키마 변경이 필요하면(예: 일일 카운트 영속) create_all/`--force` 재시딩 관행.
- 배포: `intraday_enabled=True`로 운영 서버(`dashboard.sh`가 기동하는 `simcore.live run`)에서 활성화. 첫 가동 시 장중 로그(`dashboard.sh logs live`, tmux `trade:1`)로 매수/매도·킬스위치 동작 관측.

## 리스크 / 한계 (정직 고지)

- 인트라데이 매매는 백테스트로 검증되지 않았다(감사 3단계 미이행). 이 기능은 **관측·탐색 목적의 페이퍼 실험**이며, 실전 판단 근거로 삼지 않는다.
- 체결강도는 KR 라이브 전용(US·리플레이 부재). 지표 신뢰도는 KIS 데이터 품질에 종속.
- 잠정봉 기반 신호는 장중 가격 흔들림에 따라 변동 → 휩쏘 캡·쿨다운으로 완화하나 완전 제거는 아님.
