# simcore 매매 엔진 코어 — 설계 스펙

- 날짜: 2026-07-07
- 상태: 사용자 승인 완료 (브레인스토밍 세션)
- 상위 문서: 주식 자동매매 모의투자 시뮬레이터 기획서 v1

## 1. 배경과 서브프로젝트 분해

기획서 전체는 하나의 스펙으로 다루기에 너무 크다. 아래 순서로 서브프로젝트를 나누고,
각각 스펙 → 구현 계획 → 구현 사이클을 반복한다.

1. **매매 엔진 코어 (이번 스펙)** — 순수 로직 + 과거 데이터 리플레이 검증
2. KIS 실시세 연동 + 스케줄러 + DB 영속 (라이브 모드)
3. 대시보드 (React 메인/캐릭터 상세 화면, WebSocket) — 화면 구성·디자인은 이 단계에서 별도 브레인스토밍
4. 감정분석·뉴스·수급 신호 (신호 8~10번) — 키워드 기반 → Claude API 고도화
5. 해외 캐릭터 정교화(서머타임·환전 정밀화) 및 운영 안정화

## 2. 이번 서브프로젝트의 목표

청신호/적신호 카운트 규칙(매수 7 / 매도 3)이 실제 과거 데이터에서 어떻게 동작하는지를
**KIS 키·DB·화면 없이** 검증할 수 있는 순수 Python 엔진을 만든다.

## 3. 아키텍처: 이벤트 구동 코어

엔진은 시계도 외부 API도 모른다. 외부에서 이벤트를 주입하면 주문/체결 기록을 반환한다.

- 입력 이벤트: `일봉 확정(on_daily_close)`, `가격 틱(on_price_tick)` 두 가지
- 출력: 주문/체결 기록, 포지션·현금 상태
- **리플레이 모드**(과거 데이터를 루프로 주입)와 **라이브 모드**(다음 단계에서
  스케줄러가 실시간 주입)가 완전히 동일한 코드 경로를 탄다.

### 패키지 구조

```
simcore/
├── config.py       # 모든 튜닝 파라미터 (docs/trading-rules.md 와 1:1 대응)
├── models.py       # Character, Position, Trade, DailyBar, PriceTick
├── indicators.py   # SMA·RSI·MACD·볼린저·스토캐스틱 (일봉 시계열 → 지표값)
├── signals.py      # 청신호 1~7, 적신호 1~7 판정. 신호 8~10은 인터페이스만 (항상 꺼짐 스텁)
├── costs.py        # 수수료·거래세·환전 수수료·슬리피지
├── portfolio.py    # 캐릭터별 현금·포지션·평가액·실현손익 + 회계 불변식
├── engine.py       # 이벤트 처리, 7/3 규칙, 우선순위, 포지션 사이징, 쿨다운
└── replay.py       # pykrx(국내)·yfinance(미국) 과거 일봉 → 이벤트 스트림, CLI
```

## 4. 핵심 설계 결정

### 4.1 신호 기준봉: 일봉 신호 + 5분 손익절

- 청/적신호는 **일봉 확정 데이터** 기준으로 계산한다 (기획서 신호가 모두 일봉 지표).
- 5분 주기(라이브) / 일중 근사(리플레이)에서는 **손절 -7% / 익절 +15%만** 체크한다.

### 4.2 체결 모델: 다음 날 시가

- 일봉 확정 후 낸 신호 주문은 **다음 거래일 시가**에 체결한다.
- 이유: 미래 참조(look-ahead bias) 차단. "그날 종가를 알고 그날 매수"하면
  백테스트 성과가 실제보다 부풀려진다.
- 손절/익절은 트리거 가격(리플레이) 또는 현재가(라이브)로 즉시 체결.

### 4.3 리플레이의 일중 근사 (5분봉 과거 데이터 부재 대응)

- 당일 저가 ≤ 손절가 → 손절 체결로 간주
- 당일 고가 ≥ 익절가 → 익절 체결로 간주
- 하루에 둘 다 해당하면 **손절 우선** (성과를 부풀리지 않는 보수적 처리)

### 4.4 신호 8~10 스텁에 따른 임계값 주의 ★

감정·수급 신호(청/적 각 8~10번)가 스텁(항상 꺼짐)인 동안, 켜질 수 있는 청신호 최대치는
7개다. 즉 **매수 임계값 7 = 기술 신호 7개 전부 충족**이라는 뜻이 되어 매매가 극히
드물어질 수 있다. 따라서:

- 임계값은 `config.py` 설정값으로 두고, 리플레이 실험에서는 낮춰서(예: 5) 실험 가능하게 한다.
- 리플레이 결과에 **신호 개수 분포 리포트**(종목-일자별 청신호 개수 히스토그램)를 포함해
  임계값 튜닝의 근거를 남긴다.
- 신호 8~10이 실제로 붙는 4단계에서 임계값 7의 의미가 원래 의도대로 복원된다.

### 4.5 캐릭터와 통화

| 캐릭터 | 유니버스 | 통화 | 초기 자금 |
|---|---|---|---|
| 국내형 | 코스피200 | KRW | 1억 원 |
| 해외형 | S&P500 | USD | 1억 원을 시작 시점 환율로 환전 |
| 범용형 | 코스피200 + S&P500 | 혼합 | 1억 원 |

- 환율은 일별 환율 시계열 사용. 해외 자산 평가액은 매일 환율로 원화 환산.
- 매매 규칙·임계값은 세 캐릭터 동일 (설정으로 캐릭터별 오버라이드 가능 구조).

### 4.6 비용 모델 기본값 (전부 설정값)

| 항목 | 기본값 |
|---|---|
| 국내 매매 수수료 | 0.015% (매수/매도 각각) |
| 국내 증권거래세 | 매도 시 0.15% |
| 미국 매매 수수료 | 0.09% (매수/매도 각각) |
| 환전 수수료 | 0.1% |
| 슬리피지 | 0% (on/off 가능) |

## 5. 매매 규칙 상세

신호 20개의 정확한 계산식·파라미터·판정 흐름은 **`docs/trading-rules.md`** 가 단일
기준 문서(single source of truth)다. 설정을 바꾸면 그 문서도 함께 갱신한다.

## 6. 데이터와 에러 처리

- 과거 데이터: pykrx(코스피200 일봉), yfinance(S&P500 일봉), 일별 환율.
  다운로드 결과는 로컬 parquet으로 캐시. 캐시도 없고 다운로드도 실패하면 명확한 에러로 중단.
- 상장 20일 미만 등 데이터 부족 → 해당 종목 신호 계산 불가 처리(모두 꺼짐).
- 거래정지·결측일 → 해당 종목 스킵. 보유 중이면 마지막 가격으로 평가 + 경고 기록.
- 상장폐지 → 마지막 가격으로 강제 청산 기록.

## 7. 테스트 전략

1. 지표 단위 테스트 — 손으로 계산한 소규모 시계열과 대조.
2. 신호별 테스트 — 합성 데이터로 신호 14개가 각각 정확한 조건에서 켜지고 꺼지는지 검증.
3. 엔진 시나리오 테스트 — 매수/매도 임계값, 손절·익절 동시 발생 시 손절 우선,
   5종목 제한, 쿨다운, 현금 부족 스킵, 재매수 방지.
4. 회계 불변식 — 모든 거래 후 `현금 + 포지션 평가액 = 총자산`, 현금 음수 금지.
5. 리플레이 통합 테스트 — 고정 fixture 데이터셋으로 결정론적 결과 확인.

## 8. 완료 기준

1. `python -m simcore.replay --start 2025-01-01 --end 2025-12-31` 실행 시
   3캐릭터 수익률 요약 + 거래내역 CSV + 자산곡선 CSV + 신호 분포 리포트가 나온다.
2. 같은 기간 코스피200·S&P500 매수후보유 벤치마크와 나란히 비교된다.
3. pytest 전체 통과.
4. 리플레이 실행 기록이 `docs/experiments/` 에 남는다 (실행일·설정 스냅샷·결과 요약).

## 9. 시크릿 관리 (이후 단계 대비, 지금 규칙 확정)

- KIS 앱키/시크릿/계좌번호는 `.env` 에만 보관. 사용자가 직접 편집하며,
  AI 도구는 이 파일을 읽지 않는다.
- `.env.example` 로 필요한 변수 목록을 문서화. `.gitignore` 에 `.env` 와 토큰 캐시 등록.
- 코드는 pydantic-settings 로 로드, 키가 로그·에러에 노출되지 않게 처리.
- `KIS_ENV=paper|real` 스위치로 모의/실전 도메인 전환.
