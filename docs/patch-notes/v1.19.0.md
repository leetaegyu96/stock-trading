# v1.19.0 — 2026-09-03

"회전 억제" 가설을 검증했다. **가설은 틀렸고, 그 과정에서 라이브↔백테스트의 근본적인 불일치를 찾았다.**

## Fixed

### 1. 깨진 일봉이 허위 손절을 유발하던 문제 (PR #73)

pykrx 가 드물게 `open=high=low=0` 이고 close 만 채워진 봉을 준다(거래정지·데이터 공백). 그대로 쓰면 `Engine.check_stops` 가 `low(0) <= stop_px` 로 판정해 **그 종목 보유분을 전부 허위 손절**시킨다.

실측(2023-01~2026-09): KR 캐시 34,578봉 중 **20봉(0.058%)** 해당, US 0봉, 운영 DB(KIS 수신분) 8,380봉도 **0봉** → **백테스트만 오염**돼 있었다.

`data.sanitize_ohlcv` — 0 이하·NaN 행은 버리고, 반올림으로 어긋난 high/low 는 max/min 으로 보정. 로더 fetch 경로 + **캐시 read 경로** + `run_replay` 진입부에 모두 적용(재수집 불필요).

### 2. 트레일링 잠금선의 장중 래칫 — 라이브만 하던 동작

`LiveScheduler.build()` 에서 **`tick_{market}` 잡은 `intraday_enabled` 블록 밖에서 무조건 등록**된다. 즉 운영은 지금(`INTRADAY_ENABLED=0`)도 5분마다 `on_tick` → `check_stops` → `_update_trailing` 으로 **잠금선을 장중에 계단식으로 올린다.** 그러면 **같은 날 되돌림이 그 올라간 선을 때려 청산**된다.

`run_replay` 는 하루 1회 일봉으로만 판정한다 — 저가를 **갱신 전** 잠금선과 비교한 뒤 peak 를 올리므로, 올라간 선은 다음 날부터 적용된다. **백테스트가 라이브보다 관대했고, 지금까지의 국내형 성과는 그만큼 과대평가돼 있었다.**

예 (`tests/test_engine_trailing_ratchet.py` 로 고정): 평단 100 · 잠금선 120 → 당일 고가 145 로 잠금선 **134.85** 래칫 → 저가 131 이 때려 **당일 트레일링 청산**. 하루 1회 판정에서는 생존.

## Added

- **`TradeRules.trailing_intraday_update`** (기본 `True` = 기존 동작). `False` = 손절 체크는 장중에도 계속하되 **peak/잠금선은 마감에서만** 갱신.
- `TradeRules.intraday_buy_enabled` · `intraday_max_buys_per_day` — 장중 매수 억제 브레이크(기본값 = 기존 동작).
- `replay.IntradayReplayOptions.tick_only` — 매매 판정 없이 **손익절 틱만**. 라이브 tick 잡이 매매 토글과 무관하므로 `intraday_enabled=False` 에서도 동작한다. **앞으로 백테스트는 이걸 켜야 라이브와 같은 조건이다.**
- env: `TRAILING_INTRADAY_UPDATE` / `INTRADAY_BUY_ENABLED` / `INTRADAY_MAX_BUYS_PER_DAY`
- 테스트 29건. 전체 **501 passed**.

## 검증

### 듣지 않은 것 — 매수 회전 억제

2026 8개월, 4슬라이스, 기준 = 장중 OFF:

| 설정 | 국내형 | 범용형 |
|---|---|---|
| ON 브레이크 없음 | −10.1%p | +7.3%p |
| ON + **장중매수 금지** | **−13.1%p** (더 나쁨) | −1.3%p |
| ON + 하루 상한 1 / 2 / 3 | −12.3 / −7.1 / −6.3%p | −4.8 / −1.2 / +3.9%p |

매수를 완전히 막으면 오히려 더 나쁘고, 국내형 반응이 비단조다. 결정적으로 같은 설정을 `high_first` 로 돌리면 국내형 +34.50% → **+17.71%**(16.8%p) — **경로 가정이 브레이크 간 차이보다 크게 흔든다.** 두 브레이크는 기본값으로 남긴다.

### 듣는 것 — 트레일링 장중 래칫 차단

래칫 OFF 가 ON 대비 개선폭 (3구간 × 경로 양방향, 8슬라이스 틱 모사):

| 구간 | 국내형 | 범용형 | 해외형 |
|---|---|---|---|
| 2026-01 ~ 09 | **+15.90 ~ +18.79%p** | −1.11 ~ −1.83%p | −0.07%p |
| 2024-07 ~ 2025-07 | **+9.57 ~ +9.58%p** | −1.79%p | 0.00%p |
| 2023-07 ~ 2024-07 | **+12.58 ~ +14.56%p** | +8.57 ~ +11.07%p | 0.00%p |

국내형 **6/6 조합 전부 개선**. 범용형 4/6. 해외형 무영향(US 일중 변동폭이 좁아 래칫-되돌림 조합이 거의 없다).

**정합성 확인**: 래칫을 끄면 결과가 하루-1회 기준선과 **소수점까지 일치**한다(거래 499, 트레일 59, 손절 98, 국내형 +44.59%). 잠금선이 장중에 변하지 않으면 슬라이스별 손절 체크가 일봉 저가 체크와 동치가 되기 때문 — 구현이 의도대로 동작한다는 증거다.

> 새 알파가 아니다. **라이브가 백테스트에 없던 동작을 했고 그게 KR 에서 해로웠다.** 끄는 것은 라이브를 이미 검증된 일봉 동작에 맞추는 일이다.

## Changed — 운영

`.env` 에 **`TRAILING_INTRADAY_UPDATE=false`** 적용. 손절·트레일링 청산 자체는 그대로 작동하며, 잠금선 상향만 마감으로 미룬다. `INTRADAY_ENABLED=0` 유지.

## 남은 한계

경로 가정의 폭이 브레이크 간 차이보다 크다는 것은 **일봉 기반 하니스로 장중 파라미터를 튜닝할 수 없다**는 뜻이다. 장중 매매를 진지하게 되살리려면 실제 분봉/틱 데이터가 필요하다. 그전까지 이 하니스의 쓰임은 **메커니즘 확인과 방향성**까지다.
