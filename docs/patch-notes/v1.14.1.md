# v1.14.1 — 2026-07-21

**핫픽스: KIS 토큰 만료(EGW00123, HTTP 500/200) 자동 재발급 — 장중 조용한 시세 조회 전면 실패 복구.**

## Fixed

- **토큰 만료 시 시세 조회가 조용히 전부 실패하던 버그 수정 (#48).** 운영 중 저장된 KIS
  액세스 토큰이 만료된 뒤 `current_price` 등 조회가 계속 실패해, `on_intraday`가 전 종목
  현재가를 못 받아 `snaps`가 비고 조기 return → 매매·가드 기록 0. 로그가 없어 장중
  자동매매가 매매 없이 빈 스캔만 반복하는 것을 눈치채기 어려웠다.
- **근본 원인.** KIS는 토큰 만료를 HTTP 401이 아니라 **500(또는 200) + 본문**으로 응답한다:
  `{"rt_cd":"1","msg_cd":"EGW00123","msg1":"기간이 만료된 token 입니다."}`. 기존
  `KisClient._get()`는 401일 때만 토큰을 무효화·재발급했고 500은 백오프 재시도만 해서
  **같은 만료 토큰을 영원히 재사용**했다. 또한 `_token()`은 저장된 `expires_at`이 미래면
  캐시 토큰을 그대로 반환해, KIS가 토큰을 조기 무효화한 경우(같은 앱키로 재발급 등)에도
  낡은 토큰을 계속 썼다.
- **수정.** 응답 **본문**을 파싱해 만료 토큰 에러를 판정하는 `_is_expired_token()` 추가
  (상태코드만으로는 일반 500 서버오류와 구분 불가). `_get()`은 이제 401 **또는** 만료 본문이면
  토큰을 무효화하고 재발급 후 재시도한다. 강제 무효화(`store.save("", 0.0)`)라 `expires_at`이
  아직 미래여도 조기 무효화 케이스까지 복구된다.

## 안정성

- `reissued` 플래그로 **요청당 토큰 재발급 1회**로 제한 — 재발급 후에도 만료 에러면 즉시 포기.
  무한재시도와 토큰 발급 rate limit(EGW00133, 1분당 1회) 폭주를 방지한다. 기존 401 경로도
  동일 정책으로 일관화(이전엔 요청당 최대 3회까지 재발급 가능했음).

## 검증

- pytest **375 passed**(+4). 신규 회귀 테스트: 만료 본문 HTTP 500/200 → 재발급 복구,
  일반 500 → 재발급 없이 백오프(오판정 가드), 재발급 후에도 만료 → 요청당 1회만 재발급 후 포기.
  TDD로 버그 재현(복구 실패)→수정 실증.

## 운영 반영

- 데몬 재기동만 하면 적용(설정 변경 없음). 재기동 후 만료 토큰은 첫 조회에서 자동 재발급된다.
