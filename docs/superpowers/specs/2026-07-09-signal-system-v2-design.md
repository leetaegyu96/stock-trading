# 신호 시스템 v2 (점수제·게이팅·트레일링 스탑) — 설계 스펙

- 날짜: 2026-07-09
- 상태: 사용자 승인 완료 (브레인스토밍 세션)
- 상위 문서: 주식 자동매매 모의투자 시뮬레이터 기획서 — 서브프로젝트 4(신호 고도화)
- 목표: **수익 극대화보다 손실 최소화.** 매수는 매우 까다롭게(다중 확인), 매도는 빠르게.
- 단일 기준 문서(구현 후): `docs/trading-rules.md` (v2로 재작성)

## 1. 배경

기존 v1은 "청신호 개수 ≥ 임계값(7)" 카운트 방식이었다. v2는 **신호별 점수 + 카테고리 상한 +
매수 다중 게이팅 + 매도 등급 + 트레일링 스탑**의 보수적 전략으로 교체한다. 사용자가 GPT와
정리한 "최종 권장안 v2"를 반영한다.

이 서브프로젝트는 엔진 코어(`simcore/`)를 실제로 수정한다(부분매도·트레일링스탑·게이팅). 라이브
계층/대시보드는 이 단계에서 건드리지 않으며, 완료 후 데이터 리셋 → 최근 6개월 리플레이를 돌린다.
UI 개편은 별도 서브프로젝트 5.

## 3. 점수 계산 (카테고리 상한)

각 신호는 점수를 갖고, **카테고리별 상한**을 적용한 뒤 합산한다(같은 계열 신호 과다 가중 방지).

| 카테고리 (청 / 적) | 상한 |
|---|---|
| 추세 | 10 |
| 돌파(청) / 하락패턴(적) | 10 |
| 거래량 | 8 |
| 모멘텀 | 8 |
| 변동성 | 6 |

`총점 = Σ min(카테고리 점수합, 카테고리 상한)`. 청/적 각각 계산. 상한은 청·적 모두 적용하며,
청신호의 "돌파" 슬롯은 적신호에서 "하락패턴" 슬롯(R18·스텁 R22/R25~30)에 대응한다(상한 10 동일).

## 4. 매수 규칙 (다중 게이팅) ★엔진 변경

- 관심(12+)·후보(15+)는 표기용 등급. **실제 매수는 총점 ≥ 18 AND 아래 3조건 모두 충족:**
  - **돌파** 중 1개 이상: G18 · G7 · G19(스텁이라 현재 G18·G7)
  - **거래량** 중 1개 이상: G5 · G13 · G23
  - **추세** 중 1개 이상: G1 · G4 · G11 · G12 · G15
- 우선순위(현금·슬롯 배분): 총점 내림차순 → 당일 등락률 → 거래량.
- 하락장 가드(권장, 설정): 시장/종목이 20일선 아래면 매수 임계값을 높이거나 신규매수 제한
  (v2 최초 구현에서는 설정값 `bear_market_guard` 스위치로 두되 기본 off — 후속에서 시장추세 연동).

## 5. 매도 규칙 ★엔진 변경

적신호 총점 기준:

| 총점 | 조치 |
|---|---|
| 0~5 | 보유 |
| 6~8 | 주의(보유, 기록만) |
| 9~10 | **부분 매도(보유 수량의 50%)** |
| 11+ | 전량 매도 |

- **강제 매도**(점수 무관, 즉시 전량): R7(−7% 손절) · 트레일링 스탑 발동 · R18(지지선 붕괴) ·
  R5+R23(거래량 급증 음봉 + 장대 음봉 동시).
- 부분 매도는 포지션을 남기므로 **쿨다운 없음**; 전량 매도(신호/강제)는 쿨다운 2거래일 적용.

## 6. 트레일링 스탑 ★엔진 변경 (기존 +15% 고정 익절 대체)

포지션별로 **진입 후 최고가(peak)**와 **잠금 손절 등급(locked stop, 평단 대비 %)**을 추적한다.
초기 잠금 손절 = −7%. peak 수익률이 아래 구간을 넘으면 잠금 손절을 상향(락인):

| peak 수익률 도달 | 잠금 손절(평단 대비) |
|---|---|
| +10% | 0% (본전) |
| +20% | +10% |
| +30% | +20% |
| +40% | +30% |
| +40% 초과 | 최고가 대비 −`trail_pct`(기본 7%) |

- 매 종가·5분 체크 시: peak 갱신 → 잠금 손절 갱신 → **현재가 ≤ 잠금 손절선(또는 +40%초과 구간의
  최고가 트레일선)이면 전량 매도**(사유 = 트레일링 스탑, R10).
- −7% 손절(R7)은 잠금 손절의 초기값으로 자연 포함된다.

## 7. 설정 (`simcore/config.py` 확장)

- `SignalScores`: 코드→점수 매핑, 코드→카테고리 매핑, 카테고리 상한.
- `TradeRules` v2: `buy_score_interest=12`, `buy_score_candidate=15`, `buy_score_min=18`,
  `sell_partial_min=9`, `sell_full_min=11`, `partial_sell_fraction=0.5`,
  `stop_loss_pct=-0.07`(잠금손절 초기값), 트레일링 단계 테이블, `trail_pct=0.07`,
  `bear_market_guard=False`. 기존 `take_profit_pct`(+15%)는 제거(트레일링으로 대체).
- 지표 파라미터: ADX 기간(14)·ADX 임계(25)·일목(9/26/52)·SAR(가속 0.02/최대 0.2)·
  ATR 기간(14)·OBV·VWAP 기간 등.

## 8. 신호 평가 인터페이스 진화 (`simcore/signals.py`)

- `evaluate_frame(df, params)`: 구현 신호 전부 + 스텁 컬럼(False)을 포함한 boolean 표(기존과 동일 형태, 컬럼 확장).
- 신규 순수 함수 `score(fired_codes, scores) -> ScoreResult`:
  `total`, `by_category`(상한 적용 후), `gate_ok`(돌파·거래량·추세 각 1+). 청/적 각각.
- `fired_at(frame, d)`: 기존 (green_codes, red_codes) 유지(스텁 제외한 실제 발화 코드).
- `SymbolSnapshot`(models.py) 확장: 기존 `green`/`red`(코드 튜플)에 더해
  `green_score:int`, `red_score:int`, `buy_gate:bool` 추가. 엔진은 이를 소비.
  (리플레이/라이브 orchestrator가 snapshot 생성 시 score/gate 계산해 채운다.)

## 9. 엔진 변경 (`simcore/engine.py`, `simcore/portfolio.py`)

- `evaluate_close`: 매수 후보 = `green_score ≥ buy_score_min AND buy_gate`. 매도 =
  red_score 등급(부분/전량) + 강제 조건. 우선순위 = green_score 내림차순.
- `Position`에 `peak_price: float`, `locked_stop_pct: float` 추가(진입 시 초기화).
- `check_stops`: 트레일링 스탑(peak 갱신·잠금손절 갱신·트리거 매도)로 재작성. 리플레이 일중
  근사는 당일 고가로 peak 갱신, 당일 저가로 손절 트리거(보수적: 손절 우선).
- `portfolio.sell`에 부분 매도 지원: `quantity` 인자(미지정=전량). 부분 매도 시 평단/피크 유지.
- 회계 불변식(현금+평가액=총자산, 음수 금지)은 유지.

## 11. 테스트 전략

1. **지표 단위**: 신규 지표(ADX·DI·일목·SAR·OBV·VWAP·ATR)를 손계산 소규모 시계열과 대조.
2. **신호별**: 각 구현 신호가 정확한 합성 조건에서 켜지고 꺼지는지. 스텁은 항상 False.
3. **점수/게이트**: 카테고리 상한 적용, 게이트(돌파·거래량·추세) 정확성, 경계값(총점 17→미매수, 18→매수).
4. **엔진 시나리오**: 매수 게이팅, 매도 등급(9~10 부분·11+ 전량), 강제매도(−7%·지지선·장대음봉+거래량),
   트레일링 스탑(락인 단계·최고가 트레일), 부분매도 후 쿨다운 없음/전량 후 쿨다운, 5종목·현금부족·재매수금지.
5. **회계 불변식**: 부분/전량/강제 매도, 트레일링 후 총자산·현금 정합.
6. **리플레이 통합**: 고정 fixture 결정론 결과.
7. 기존 63 엔진 테스트 중 규칙 변경으로 깨지는 것은 v2 규칙에 맞게 갱신(임계값·익절→트레일링 등).

## 12. 완료 기준

1. `python -m simcore --start 2026-01-01 --end 2026-07-09` 실행 시 3캐릭터 결과 + 거래내역(신호·점수 포함)
   + 자산곡선 + 신호 점수 분포 리포트가 나온다.
2. pytest 전체 통과(신규 + 갱신).
3. **데이터 리셋 → 최근 6개월(2026-01-09~2026-07-09) 리플레이** 실행, 결과를 `docs/experiments/`에 기록
   (실행일·설정 스냅샷·캐릭터별 TWR/MDD/거래수/승률·대표 거래 몇 건의 점수 근거).
4. `docs/trading-rules.md` v2로 갱신, config와 1:1.
