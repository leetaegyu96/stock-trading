# 매매 규칙서 (trading-rules) v2

이 문서는 시뮬레이터의 매매 판정 로직 **단일 기준 문서**다.
`simcore/config.py` 의 모든 설정값과 1:1 대응하며, 설정을 바꾸면 이 문서도 함께 갱신한다.
코드를 읽지 않아도 이 문서만으로 "왜 이 종목을 샀는지/팔았는지" 재구성 가능해야 한다.

- 최종 갱신: 2026-07-09 (v2 — 점수제·다중 게이팅·매도 등급·트레일링 스탑)
- 설계 스펙: `docs/superpowers/specs/2026-07-09-signal-system-v2-design.md`
- 튜닝 이력: 실험 결과는 `docs/experiments/` 참조

v1(청신호 개수 ≥ 7 / 적신호 개수 ≥ 3 카운트 방식)은 폐기되었다. v2는 **신호별 점수 + 카테고리
상한 + 매수 다중 게이팅 + 매도 등급 + 트레일링 스탑**으로 대체한다. 목표는 수익 극대화가 아니라
**손실 최소화**: 매수는 다중 확인을 요구해 까다롭게, 매도는 등급에 따라 빠르게 대응한다.

## 1. 판정 주기와 체결 규칙

| 단계 | 시점 | 하는 일 |
|---|---|---|
| 신호 판정 | 일봉 확정 시 (장 마감 후) | 유니버스 전 종목 청/적신호 점수·게이트 계산 → 매수/매도 예약 |
| 신호 주문 체결 | **다음 거래일 시가** | look-ahead bias 방지를 위해 당일 체결 금지 |
| 손절/트레일링 스탑 | 장중 5분마다 (라이브) / 일중 OHLC 근사 (리플레이) | 신호와 무관하게 즉시 체결 |

리플레이 일중 근사: 당일 고가로 peak(포지션 최고가)를 먼저 갱신한 뒤 잠금 손절선을 갱신하고,
당일 저가 ≤ 잠금 손절선(또는 트레일선)이면 트레일링 스탑 체결. **손절 우선**(보수적 처리)이며
기존 v1의 +15% 고정 익절(R10)은 트레일링 스탑으로 완전히 대체되어 더 이상 존재하지 않는다.

## 2. 신규 지표 (`simcore/indicators.py`)

기존 SMA·RSI·MACD·볼린저·스토캐스틱에 아래를 추가:

- **ADX, DI+/DI−** — 추세 강도/방향 (`adx_period=14`, `adx_threshold=25.0`)
- **일목균형표(Ichimoku)** — 전환선(9)·기준선(26)·선행스팬A/B(→구름, 52) (`ichimoku_tenkan=9`,
  `ichimoku_kijun=26`, `ichimoku_senkou_b=52`)
- **Parabolic SAR** — 추세 반전 추적 (`sar_af_step=0.02`, `sar_af_max=0.2`)
- **OBV(On-Balance Volume)** — 누적 거래량 방향
- **VWAP(롤링)** — 거래량 가중 평균가 (`vwap_period=20`)
- **ATR(Average True Range)** — 변동성 (`atr_period=14`)

## 5. 점수 계산 (카테고리 상한)

각 신호는 점수를 갖고, **카테고리별 상한**(`SignalScores.caps`)을 적용한 뒤 합산한다
(같은 계열 신호 과다 가중 방지). `총점 = Σ min(카테고리 점수합, 카테고리 상한)`. 청신호(매수)/
적신호(매도) 각각 독립 계산한다.

| 카테고리 (청 / 적) | 상한 |
|---|---|
| 추세 | 10 |
| 돌파(청) / 하락패턴(적) | 10 |
| 거래량 | 8 |
| 모멘텀 | 8 |
| 변동성 | 6 |

## 6. 매수 규칙 (다중 게이팅) — `buy_score_min=18`

점수 등급(표기용):

| 총점 | 등급 |
|---|---|
| 12+ | 관심 (`buy_score_interest`) |
| 15+ | 후보 (`buy_score_candidate`) |
| 18+ AND 게이트 충족 | **매수** (`buy_score_min`) |

**실제 매수는 총점 ≥ 18 AND 아래 3개 게이트 집합에서 각 1개 이상 발화**(`SignalScores.buy_gate`):

- **추세**: G1 · G4 · G11 · G12 · G15 중 1개 이상
- **돌파**: G7 · G18 중 1개 이상
- **거래량**: G5 · G13 · G23 중 1개 이상

우선순위(현금·슬롯 배분): 총점(green_score) 내림차순 → 당일 등락률 → 거래량.

하락장 가드: 캐릭터별 스위치 `bear_guard_characters`(기본 **전체 off**, 빈 집합). CLI
`--bear-guard`(전체 강제 on) / `--no-bear-guard`(전체 강제 off)로 opt-in/opt-out. 상세는 §6-1,
튜닝 결과는 §6-1 말미 참조.

### 6-1. 하락장 가드 v2 (시장 지수 추세 필터 — 캐릭터 전 시장 하락 시만 차단)

시장 대표 지수(국내=코스피200, 해외=S&P500)의 **이동평균**을 매일 계산해 시장별 하락장 여부를
판정한다. SMA 기간은 시장별로 독립 설정한다: `market_trend_period_kr`(기본 20) ·
`market_trend_period_us`(기본 20). 이 기간은 캐릭터가 가드 대상으로 opt-in됐을 때만 쓰인다.

- **판정**: 지수 종가 < 지수 해당 시장 SMA → 해당 시장 **하락장**.
- **차단 조건(v2)**: `st.spec.name in bear_guard_characters` **AND** **캐릭터가 거래하는 모든
  시장이 하락장일 때만**(`all(bearish_by_market[m] for m in 캐릭터.markets)`) 그 캐릭터의
  신규 매수를 차단한다. 즉 가드는 캐릭터 단위로 켜고 끄며(`bear_guard_characters`에 캐릭터
  이름이 있어야 판정 자체가 걸린다), 켜진 캐릭터에 대해서만 위 시장 하락 조건을 본다.
  - **단일시장 캐릭터**(국내형=KR만, 해외형=US만): 가드가 켜져 있고 자기 시장이 하락장이면
    즉시 차단 — v1과 동일하게 동작(단일시장 캐릭터는 v1·v2 리플레이 결과가 완전히 동일함 —
    `docs/experiments/replay_bear_guard_ab_2026-01-09_2026-07-09.md` A/B 참고).
  - **범용형**(KR+US 양시장): 가드가 켜져 있을 때 **두 시장이 동시에 하락장일 때만** 차단한다.
    한쪽 시장만 하락해도 차단하지 않는다 — v1은 한쪽 시장만 하락해도 전체를 막아 과발동했던
    문제를 해소한 것이 v2의 핵심 변경.
- **적용 범위**: 신규 매수만 차단한다. 이미 보유 중인 종목의 매도·손절·트레일링 스탑은
  영향받지 않고 그대로 동작한다(리스크 관리 로직은 시장 추세와 무관하게 항상 작동).
- **기본값**: `bear_guard_characters=frozenset()`(전체 off) — 지수 데이터가 없거나 로드되지
  않은 경우에도 가드는 발동하지 않는다(안전한 기본 동작).
- **활성화**: CLI 리플레이 실행 시 `--bear-guard` 플래그로 전 캐릭터 강제 on, `--no-bear-guard`로
  전체 강제 off한다(둘은 상호 배타). (`python -m simcore ... --bear-guard`) 특정 캐릭터만
  적용하려면 `Config.rules.bear_guard_characters`에 캐릭터 이름 집합을 지정한다.
- **튜닝 결과(2026-01-09~2026-07-09 스윕 + 12개월 검증)**: `market_trend_period_kr/us`를
  20·40·60·120일로 스윕하고 채택 규칙(TWR≥OFF−1%p AND MDD 개선 → MDD 최소)을 적용한 뒤
  12개월 창(2025-07-10~2026-07-09)에서 재검증했다. 결과, **국내형은 가드를 걸면 모든 기간에서
  TWR이 OFF보다 낮아** 가드 대상에서 영구 제외 권장. 해외형·범용형은 6개월 창에서는 MDD가
  개선되는 후보(둘 다 kr=20,us=20)가 나왔지만, 12개월 창에서는 **두 후보 모두 MDD가 OFF보다
  악화**되어 스펙 §1의 검증 게이트(MDD 개선 방향 유지)를 통과하지 못했다. 6개월 단일 창의
  개선은 그 구간 특유의 국면에 대한 과적합이었던 것으로 판정한다. 이에 따라 **기본값은 전체
  off로 확정**됐고, 국면 판단이 서면 향후 `--bear-guard` 또는 특정 캐릭터 집합으로 opt-in할 수
  있도록 인프라(캐릭터별 스위치 + 시장별 기간)만 남겨둔다. 상세 데이터와 근거는
  `docs/experiments/bear_guard_tuning_sweep_2026-01-09_2026-07-09.md` 참고.

## 7. 매도 규칙 (등급) — `sell_partial_min=9` / `sell_full_min=11`

적신호 총점(red_score) 기준:

| 총점 | 조치 |
|---|---|
| 0~5 | 보유 |
| 6~8 | 주의(보유, 기록만) |
| 9~10 | **부분 매도**(보유 수량의 `partial_sell_fraction`=50%) |
| 11+ | 전량 매도 |

**강제 매도**(점수 무관, 즉시 전량):
- R7 — 잠금 손절 도달
- 트레일링 스탑 발동(R10)
- R18 — 지지선(최근 저점) 붕괴
- R5 + R23 동시 발화 — 거래량 급증 음봉 + 장대 음봉

부분 매도는 포지션을 남기므로 **쿨다운 없음**(평단·피크 유지). 전량 매도(등급/강제 불문)는
**쿨다운 2거래일**(`cooldown_days`) 적용.

## 8. 트레일링 스탑 (v1의 +15% 고정 익절을 대체)

포지션별로 진입 후 **최고가(peak)**와 **잠금 손절 등급(locked stop, 평단 대비 %)**을 추적한다.
초기 잠금 손절 = `stop_loss_pct`(−7%). peak 수익률이 아래 구간을 넘으면 잠금 손절을 상향(락인):

| peak 수익률 도달 | 잠금 손절(평단 대비) |
|---|---|
| +10% | 0% (본전) |
| +20% | +10% |
| +30% | +20% |
| +40% | +30% |
| `trailing_top`=+40% 초과 | 최고가 대비 −`trail_pct`(7%) 트레일 |

(`TradeRules.trailing_tiers = ((0.40, 0.30), (0.30, 0.20), (0.20, 0.10), (0.10, 0.0))`, 내림차순
첫 매칭 적용.)

- 매 판정(종가) / 5분(라이브) 체크 시: peak 갱신 → 잠금 손절 갱신 → 현재가 ≤ 잠금 손절선
  (또는 +40% 초과 구간의 최고가 트레일선)이면 **전량 매도**(사유 = 트레일링 스탑, R7/R10).
- 초기 −7% 손절(R7)은 잠금 손절의 시작값으로 자연 포함된다.

## 9. 포지션 사이징 · 우선순위

- 최대 보유: 캐릭터당 **`max_positions`=5종목**.
- 1종목 배분: `가용 현금 ÷ 남은 슬롯 수` 균등 배분.
- 매수 우선순위: green_score 내림차순 → 당일 등락률 높은 순 → 거래량 많은 순.
- 현금 부족 시 매수 스킵. 매도로 현금이 생기면 다음 판정 주기에 후보 매수.
- 이미 보유 중인 종목 재매수 금지.
- **쿨다운**: 전량 매도한 종목은 **`cooldown_days`=2거래일** 재매수 금지. 부분 매도는 쿨다운 없음(§7).
- 범용형은 같은 날 국내·미국 후보가 함께 있으면 국내 시장을 먼저 처리한다(슬롯·현금을 KR 이 우선 소비). 결정론적 처리 순서이며 별도 우열 규칙은 아니다.

## 12. 사용자 입출금 규칙

- 사용자는 언제든 캐릭터별로 자금을 추가 입금하거나 출금할 수 있다.
- 입금: 현금 잔고에 즉시 반영. 해외형은 당일 환율 환전(환전 수수료 적용).
- 출금: 현금이 충분하면 즉시 차감. **부족하면 엔진이 자동 매도하지 않고**,
  사용자가 청산할 보유 종목을 직접 선택해 매도한 뒤 출금한다.
  이 매도는 거래내역에 `사유=사용자 출금` 으로 기록되며 수수료·세금이 동일하게 붙는다.
- 수익률은 입출금 왜곡을 제거한 **시간가중수익률(TWR)** 로 표시하고,
  누적 손익 금액(원)을 참고 지표로 병기한다.
- 사용자 출금으로 전량 매도된 종목도 쿨다운(2거래일 재매수 금지)이 동일하게 적용된다.
