# 트레이딩 제품·화면·신호 시스템 1차 감사

- 감사일: 2026-07-10
- 감사 범위: 시뮬레이션 코어, 라이브 실행 구조, 신호 계산, 대시보드 API, Chrome 실제 화면
- 확인 화면: 메인 대시보드(`/`), 국내형 상세(`/character/국내형`). Chrome에서 2026-07-10 13:24 KST경 실데이터가 연결된 `localhost:8000`을 확인
- 목적: 주식 초보자가 모의투자를 통해 판단 근거와 위험을 학습하고, 장기적으로 제한된 실자금 자동매매에 진입할 수 있는 제품인지 평가

> 결론부터 말하면, 현재 프로젝트는 **규칙 기반 모의매매 엔진과 성과 조회 대시보드로는 상당히 진척**됐다. 그러나 아직은 “현재 무슨 일이 벌어지고 있고 왜 다음 행동을 해야 하는지 알려주는 트레이딩 의사결정 시스템”이 아니라 **사후 성과·체결 기록 뷰어**에 가깝다. 특히 뉴스·공시·수급·시장 국면 데이터가 신호에 연결되지 않았고, 백테스트 신뢰성을 입증할 핵심 검증과 실전 안전장치가 부족하므로 **실자금 자동매매 전환은 금지**하는 것이 맞다.

## 1. 실제 화면에서 확인한 상태

### 메인 화면

- 전체 자산: `₩314,808,213`
- 국내형: 총자산 `₩138,880,192`, TWR `+38.88%`, 당일 `-0.21%`, 보유 2종목
- 해외형: 총자산 `₩100,040,915`, TWR `+16.05%`, 당일 `-0.88%`, 보유 5종목
- 범용형: 총자산 `₩75,887,105`, TWR `-12.10%`, 당일 `-0.88%`, 보유 5종목
- 오늘의 시장 상승·하락 종목, 캐릭터별 베스트·워스트 보유종목, 최근 거래가 표시됨
- WebSocket 연결 시 “실시간”과 최종 갱신 시각이 표시됨

### 국내형 상세 화면

- TWR `+38.88%`, MDD `-17.30%`, 누적손익 `+₩38,880,192`, 216건, 승률 `45.7%`
- 화면에 표시된 3개월 자산 구간 수익률은 `+27.72%`
- 보유: 신한지주 `+3.73%`, KB금융 `+7.09%`
- 거래내역은 최근 100건을 한 페이지에 전부 표시하며, 매수·매도 신호 상세를 펼칠 수 있음

### 화면상 좋은 점

- TWR과 MDD를 함께 보여 주는 방향은 옳다. 단순 누적손익만 강조하는 것보다 훨씬 낫다.
- 국내 주식 관례에 맞춘 상승=빨강, 하락=파랑과 통화별 가격 표기가 일관적이다.
- 캐릭터별 시장·기준통화·현금·보유 수를 빠르게 비교할 수 있다.
- 매매 사유와 발화 신호를 저장하고 화면에 노출한 것은 감사 가능성(auditability)의 좋은 기반이다.
- 입출금 영향을 제거한 TWR, 지연 시세 배지, 다음 거래일 시가 체결 원칙 등 코드의 기본 설계 의식은 좋다.

## 2. 즉시 수정해야 할 P0 문제

### P0-1. 엔진 행동과 화면 설명이 서로 모순된다

실제 국내형 거래내역에서 카카오뱅크와 삼성물산 매도는 `R5(거래량 급증 음봉) + R23(장대 음봉)` 조합으로 실행됐다. 규칙서상 이 조합은 점수와 관계없이 **강제 전량매도**다. 그러나 화면 요약은 `주의 신호 (8점)`으로 표시한다.

이 모순은 초보 사용자가 “주의인데 왜 전량 매도했지?”라고 오해하게 만들고, 전략 검증 결과도 불신하게 한다.

클로드 구현 요구:

- 거래 레코드에 `decision_type`(`BUY`, `PARTIAL_SELL`, `FULL_SELL`, `FORCED_SELL`)과 `trigger_rule`을 영속화한다.
- 요약 문구는 점수만 다시 계산하지 말고 **실제 엔진이 내린 결정 결과**를 우선 사용한다.
- `R5+R23`은 “급락 복합조건 → 강제 전량매도”로 표시한다.
- `R18`은 점수 등급과 무관한 “지지선 붕괴 → 강제 전량매도”로 표시한다.
- R7/R10은 “신호 없음”이 아니라 각각 “잠금 손절선 도달”, “최고가 대비 트레일링선 도달”로 표시한다.
- 회귀 테스트에 `R5+R23 score=8 → FORCED_SELL`, R18, R7, R10의 표시 정합성을 추가하고, 엔진이 반환하는 모든 강제 결정 원인을 파라미터화해 전수 검증한다.

완료 조건: 동일 거래의 `사유`, `신호 요약`, `실제 주문 수량`이 하나의 결정 유형을 일관되게 설명해야 한다.

### P0-2. 현재 신호의 범위를 사용자에게 정확히 알리지 않는다

현재 구현된 청신호 17개와 적신호 17개는 사실상 가격·거래량 기반 기술지표다. 문서상 `G8 긍정 심리`, `G9 외인·기관 순매수`는 항상 꺼진 스텁이다. 공시, 실적 발표, 컨센서스 변화, 금리·환율, 업종 상대강도, 외국인·기관 수급, 뉴스 신뢰도는 매매 판단에 연결되지 않는다.

따라서 현재 화면의 초록·빨강은 “종합 청·적신호”가 아니라 **기술적 청·적신호**라고 명확히 이름 붙여야 한다.

즉시(P0) 구현 요구:

- 구현 전까지 UI 라벨을 `기술적 매수 신호`, `기술적 매도 신호`로 제한한다.
- 현재 화면에 `뉴스·공시·수급은 판단에 반영되지 않음`을 명확히 표시한다.
- 외부 정보 축은 0점이 아니라 `미수집/판단 불가`로 표시한다. 데이터 부재를 중립 신호로 오인하면 안 된다.

후속(P1) 데이터 파이프라인 요구:

- 신호를 `가격/추세`, `거래량/수급`, `기업/공시`, `거시/시장`, `뉴스/심리`, `리스크` 6축으로 분리한다.
- 뉴스 신호는 출처, 발생시각, 종목 연관도, 긍·부정, 신뢰도, 이미 가격에 반영됐을 가능성을 함께 저장한다.
- 공시는 원문 링크와 핵심 수치 변화를 남기고, 단순 키워드 감정분석으로 매매하지 않는다.

완료 조건: 한 종목의 판단 화면에서 어떤 데이터 축이 강세·약세·미확인인지 구분되고 각 근거 시각과 출처를 역추적할 수 있어야 한다.

### P0-3. 현재 수익률만으로 실전 가능성을 판단할 수 없다

국내형 `+38.88%`는 눈에 띄지만 다음이 화면과 검증 보고서에서 충분히 증명되지 않았다.

- 같은 기간 KOSPI200/S&P500 및 단순 보유 전략 대비 초과수익
- 생존편향 없는 당시 구성종목(point-in-time universe)
- 수정주가·배당·액면분할·상장폐지 처리
- 실제 호가 스프레드, 시장충격, 주문 미체결/부분체결
- 환율의 매수·매도 시점별 적용과 환헤지 효과
- 파라미터 탐색 구간과 완전 분리된 out-of-sample 성과
- 상승·하락·횡보장별 성과와 전략 붕괴 구간
- 거래비용을 2~5배로 높인 스트레스 테스트

실제 화면에서는 국내형 카드의 벤치마크 초과수익이 보이지 않았다(`benchmark_delta`가 null일 가능성). 절대수익률만 크게 보여 주면 강한 상승장에서 베타를 실력으로 착각하기 쉽다.

클로드 구현 요구:

- 모든 성과 화면의 1순위를 `전략 vs 벤치마크`로 바꾼다.
- CAGR, 변동성, Sharpe/Sortino, Calmar, Profit Factor, 평균 손익비, 기대값/거래, 최대 연속손실, 회복기간을 추가한다.
- walk-forward와 완전 미사용 holdout 기간을 별도로 표시한다.
- 성과값마다 표본 기간, 거래 수, 비용 가정, 데이터 버전을 붙인다.
- 동일 파라미터로 최소 3개 시장 국면을 통과하기 전 “검증됨” 라벨을 금지한다.

완료 조건: 사용자가 수익률 숫자 하나가 아니라 “얼마의 위험을 감수해 벤치마크보다 얼마나 나았는지” 판단할 수 있어야 한다.

### 향후 실주문 단계의 P0 진입 조건: 자동매매 안전장치

현재 저장소의 계약은 **모의투자 엔진이며 KIS는 시세 조회 전용**이다. 따라서 아래 항목은 현재 모의투자 범위의 결함이 아니라, 사용자가 장기 목표로 밝힌 실전 자동매수·자동매도를 별도 단계 또는 별도 프로젝트로 승인할 때 반드시 먼저 충족할 P0 진입 조건이다. 현재 코드에 곧바로 실주문 기능을 추가해서는 안 된다.

필수 안전장치:

- `REPLAY / PAPER / SHADOW / LIVE` 모드를 화면 전체에 고정 표시
- 기본 모드는 PAPER, LIVE는 별도 배포·별도 키·별도 DB로 물리 분리
- 전역 킬스위치와 캐릭터별 매수 중지
- 일 손실 한도, 주 손실 한도, 최대 MDD, 최대 주문금액, 종목·업종·시장 노출 한도
- 데이터 지연, API 장애, 시계 불일치, 중복 주문, 미체결 주문 발생 시 fail-closed
- 주문 전 사전검증과 주문 후 증권사 원장 대사
- 모든 주문에 전략 버전, 데이터 시각, 결정 ID, idempotency key 기록
- 초기 실전은 자동주문이 아니라 알림 → 승인 → 소액 주문 → 제한적 자동화 순으로 승격

완료 조건: 어떤 단일 오류나 API 재시도로도 중복 주문·한도 초과 주문이 발생하지 않아야 하며, 킬스위치 시험이 자동화돼야 한다.

## 3. 신호 체계 평가: 청신호와 적신호의 균형

### 좋은 구조

- 같은 계열 신호의 중복 가중을 줄이는 카테고리 상한은 합리적이다.
- 매수에 추세·돌파·거래량의 다중 게이트를 요구하는 것은 단일 지표 매수보다 낫다.
- 부분매도, 전량매도, 잠금 손절, 트레일링 스탑으로 매도 강도를 나눈 방향도 좋다.

### 현재 불균형

1. **청·적신호 모두 기술지표에 편중**돼 있다. 여러 지표가 결국 같은 OHLCV에서 파생되므로 이름은 17개여도 독립 정보는 훨씬 적다.
2. 매수는 돌파 게이트가 필수라 추세 추종 성향이 매우 강하다. 횡보 후 가짜 돌파와 급등 추격에 취약할 수 있다.
3. 적신호는 임계값이 낮고 상관된 추세·거래량 지표가 빠르게 중첩돼 회전율과 휩쏘가 커질 수 있다. 화면의 216건은 전체 성과 기간 기준 거래 수이고 자산 차트는 3개월 구간이 선택돼 있으므로 두 값을 직접 결합하면 안 된다. 실제 전체 기간(리플레이 자료상 약 6개월) 기준 회전율과 선택 구간별 거래 빈도를 각각 분석해야 한다.
4. `R24 거래량 없는 상승` 4점은 단독 정보 가치에 비해 강할 수 있다. 상승 중 거래량 감소는 맥락 없이 약세로 단정하기 어렵다.
5. `R11 ADX 하락 전환`은 추세 약화이지 하락 방향 자체가 아니다. DI 방향과 결합하지 않으면 강한 상승 추세의 정상 감속도 적신호가 된다.
6. 손절 -7%는 모든 종목에 동일하다. 변동성이 다른 종목에 고정 퍼센트 손절을 쓰면 고변동 종목은 정상 변동에도 잘리고 저변동 종목은 손실을 과하게 허용할 수 있다.
7. 범용형이 같은 날 KR을 먼저 처리하는 것은 투자 판단이 아니라 구현 순서가 자산 배분을 결정하는 결함이다.
8. 하락장 가드가 검증 실패로 기본 OFF인 것은 정직한 결론이지만, 그렇다고 시장 국면 위험이 해결된 것은 아니다. 포지션 크기와 현금 비중 조절이 별도로 필요하다.

### 권장 재설계

- `신호 점수`와 `리스크 예산`을 분리한다. 강한 신호라고 큰 위험을 자동 허용하지 않는다.
- 고정 -7% 대신 ATR 기반 초기 손절과 포지션 사이징을 검증한다.
- 종목별 동일 금액이 아니라 `허용손실 = 자산 × 거래당 위험률` 기준으로 수량을 정한다.
- 동일 업종·동일 팩터 상관을 반영한 포트폴리오 위험 한도를 둔다.
- KR 우선 처리 대신 모든 후보를 공통 기대값/위험 점수로 정렬하고 시장별 예산을 먼저 배정한다.
- 신호가 발화해도 유동성, 갭 위험, 실적 발표 임박, 거래정지 위험을 통과해야 주문 가능하게 한다.
- 각 규칙을 제거하는 ablation test로 실제 기여도를 측정한다. 신호 개수 증가는 성과 개선의 증거가 아니다.

## 4. UI·UX 및 정보 구조 피드백

### P1. 첫 화면을 “성과판”에서 “오늘의 의사결정판”으로 바꾼다

현재는 누적 성과가 주인공이고 사용자가 오늘 확인해야 할 행동이 없다. 메인 상단 권장 순서:

1. 운영 모드, 시장 개장 상태, 데이터 최종시각, 지연/오류 상태
2. 오늘의 행동: 매수 예정, 매도 예정, 보류, 위험 경보
3. 포트폴리오 위험: 현금비중, 총 노출, 업종 집중, 일 손익, 손실한도 잔여
4. 전략 성과 vs 벤치마크
5. 시장 국면과 주요 이슈
6. 캐릭터 비교와 최근 체결

### P1. 신호를 현재 상태와 과거 체결로 분리한다

현재 신호는 거래내역 안에서만 확인할 수 있다. 사용자는 “지금 어떤 후보가 왜 대기 중인지”를 볼 수 없다.

- `오늘의 후보` 테이블: 종목, 행동, 신뢰등급, 기술/수급/뉴스/리스크 축, 주문 예정시각
- `왜 아직 안 샀나`: 점수 부족, 게이트 미충족, 슬롯 부족, 현금 부족, 리스크 차단
- `왜 보유 중인가`: 현재 적신호, 손절선, 최고가, 잠금 수익, 다음 행동 조건
- `왜 팔았나`: 실제 결정 유형, 발화 조건, 체결 차이, 이후 가격 변화

### P1. 보유종목 표에 리스크 정보가 부족하다

현재 수량·평단·현재가·평가액·손익률·보유일만 있다. 다음을 추가한다.

- 포트폴리오 비중, 업종, 진입 사유/점수
- 현재 청·적신호 점수와 변화 방향
- 손절 가격, 트레일링 가격, 손절까지 거리, 잠재 손실액
- 실적 발표일/주요 이벤트, 시세 기준시각
- 매도 예정/보류 상태

### P1. 거래내역 100건 전체 노출은 읽기 어렵다

실제 Chrome 전체 페이지 확인에서 100개 행 때문에 화면이 매우 길었고, 좁은 신호·실현손익 열의 정보 구분도 어려웠다.

- 기본 20건 + 페이지네이션/가상 스크롤
- 기간·캐릭터·종목·매수/매도·결정 유형·손익 필터
- 한 행은 핵심만, 세부는 행 확장 또는 우측 패널
- 거래 한 쌍(진입→부분매도→청산)을 하나의 포지션 생애로 묶어 표시
- CSV 내보내기보다 먼저 화면상 “거래 복기”를 제공

### P1. 지표 설명과 기간을 명시한다

- TWR 옆에 툴팁: 입출금 영향을 제거한 수익률
- MDD는 항상 음수 표기보다 `최대 낙폭 17.30%`처럼 위험량으로 표현하는 방안 검토
- 자산곡선의 `+27.72%`는 선택 구간 수익률임을 `선택 기간 수익률`로 명시해 전체 TWR과 혼동 방지
- 승률 옆에 평균이익·평균손실·손익비가 없으면 높은/낮은 승률을 해석할 수 없음

### P2. 초보자 학습 UX를 추가한다

- 전문용어 옆 `?` 도움말과 실제 차트 예시
- “이 신호의 반례”와 “틀릴 수 있는 이유”를 함께 표시
- 매수 근거와 반대 근거를 같은 비중으로 노출
- 매 거래에 사용자가 예상과 결과를 기록하는 복기 노트
- 캐릭터별 전략 차이가 현재 시장 범위 외에는 거의 없다. 모멘텀형/저변동형/방어형처럼 가설이 분명한 차이를 두거나, 현 구조라면 `시장별 계좌`로 이름을 바꾸는 편이 정확하다.

### 접근성·반응형

- 색만으로 상승/하락을 구분하지 말고 아이콘·부호·텍스트를 병행한다.
- 작은 회색 글씨와 연한 테두리의 대비를 높인다.
- 테이블 가로 스크롤 시 종목 열을 고정한다.
- 모바일에서는 거래내역을 카드형으로 바꾸고 핵심 행동과 위험을 먼저 표시한다.
- “실시간”은 WebSocket 연결 여부가 아니라 각 시장 가격의 `as-of` 시각과 지연 시간을 보여 줘야 한다.

## 5. 코드·아키텍처 피드백

### 강점

- 엔진, 라이브 오케스트레이션, 대시보드 조회가 모듈로 분리돼 있다.
- 거래 근거와 점수를 영속화하고 프론트 타입까지 연결한 구조는 확장하기 좋다.
- 테스트가 엔진·신호·비용·대시보드·라이브 계층에 폭넓게 존재한다.
- 규칙서와 실험 문서가 축적돼 있어 변경 이유를 추적하기 좋다.

### 개선 필요

- `signal_display.summarize()`가 실제 주문 결정이 아니라 발화 점수로 행동 문구를 재구성해 P0-1 모순을 만든다. 결정 결과를 이벤트로 영속화해야 한다.
- 대시보드의 “실시간” 표시는 카드 WebSocket 연결 상태일 뿐, 개별 가격의 신선도를 보장하지 않는다.
- `benchmark_delta`가 nullable인 채 핵심 카드에서 조용히 사라진다. 데이터 없음은 숨기지 말고 경고해야 한다.
- 백엔드가 조회 요청 중 KIS 현재가를 직접 가져오는 경로는 지연·rate limit·부분 실패가 UI 응답에 섞일 수 있다. 가격 수집과 조회를 분리하고 스냅샷 시각을 저장하는 편이 안전하다.
- 화면에는 전략 버전, 파라미터 버전, 데이터셋 버전이 없다. 재현 가능한 결과인지 확인하기 어렵다.
- 실전과 리플레이의 동치 테스트가 있어도 일봉 OHLC로 고가 선갱신→저가 손절을 근사하는 것은 실제 경로를 알 수 없다. 이 보수적 가정을 성과 화면에 표시하고 분봉 재검증이 필요하다.

## 6. 클로드 구현 로드맵

### 1단계 — 신뢰 회복(P0)

- 결정 이벤트 모델 도입 및 거래 설명 정합성 수정
- R5+R23, R18, R7, R10 등 모든 강제매도 원인의 화면 문구와 테스트 수정
- 기술적 신호 라벨 명확화, 미구현 데이터 축 표시
- 모든 화면에 PAPER/LIVE 모드와 데이터 기준시각 고정 노출
- 벤치마크 미수집 상태를 오류/경고로 노출

### 2단계 — 의사결정 화면(P1)

- 오늘의 후보·예정 주문·차단 사유 화면
- 보유종목별 손절선·트레일선·위험금액
- 시장 국면, 현금비중, 업종·종목 집중도
- 거래내역 페이지네이션·필터·포지션 생애 복기
- 성과 vs 벤치마크 및 위험조정 지표

### 3단계 — 전략 검증(P0, 실전 전 필수)

- point-in-time universe와 corporate action 검증
- walk-forward/holdout/시장 국면별 보고서
- 비용·슬리피지·미체결 스트레스 테스트
- 신호별 ablation과 파라미터 안정성 지도
- paper/shadow를 최소 한 달 이상 운영하며 주문 대사·데이터 장애 통계 수집

### 4단계 — 외부 정보축(P1)

- 공시·실적·수급·거시 데이터 파이프라인
- 출처·시각·신뢰도·결측 상태가 있는 증거 모델
- 종목 판단 화면의 찬성 근거/반대 근거 균형 표시
- 뉴스는 곧바로 주문하지 않고 별도 검증을 통과한 경우에만 점수 반영

### 5단계 — 제한적 실전(P0 게이트 통과 후)

- 처음에는 100만원 전액이 아니라 더 작은 위험 예산과 1종목 한도로 시작
- 알림 전용 → 사용자 승인 주문 → 소액 자동주문 순으로 단계 승격
- 일 손실·주 손실·MDD·주문금액 킬스위치 실전 리허설
- paper와 live 결정 차이를 매일 자동 대사

## 7. 실전 전환 승인 게이트

아래를 모두 통과하기 전 실자금 자동매매를 켜지 않는다.

- [ ] 행동과 설명의 불일치 0건
- [ ] 벤치마크·비용 포함 holdout 성과가 사전 기준 통과
- [ ] 최소 3개 시장 국면에서 손실 한도 내 동작
- [ ] point-in-time 데이터와 corporate action 검증 완료
- [ ] 1개월 이상 paper/shadow 무중단 운영
- [ ] 중복 주문·누락 주문·원장 불일치 0건
- [ ] 데이터 지연·API 장애·재시작·네트워크 단절 훈련 통과
- [ ] 킬스위치와 일/주 손실 한도 자동 테스트 통과
- [ ] 전략·데이터·주문 결정 전체 재현 가능
- [ ] 실전 모드는 별도 키·DB·배포환경으로 분리

## 최종 판단

현재 결과는 폐기할 수준이 아니다. 오히려 **모의매매 연구 플랫폼의 기반은 좋다.** 다만 높은 수익률 숫자와 많은 기술지표가 실전 우위를 보장하지 않는다. 다음 개발의 중심은 신호 개수를 늘리는 일이 아니라 다음 세 가지여야 한다.

1. **설명과 실제 행동의 완전한 일치**
2. **벤치마크·비용·시장 국면을 포함한 재현 가능한 검증**
3. **오늘의 결정과 최악의 위험을 먼저 보여 주는 화면**

이 세 축이 갖춰진 뒤에야 뉴스·공시·수급을 추가하고, 그 다음에 제한적 실전 자동화로 넘어가는 순서가 안전하다.
