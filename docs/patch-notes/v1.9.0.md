후보와 차단 사유, 보유 리스크(손절선·잠재손실), 거래 생애 복기, 지표 맥락을 사용자가 바로 읽는다.

마감 상태만 읽는다(요청 경로 무거운 계산·네트워크 금지, Phase A 관행).

## Added

- **엔진 매수후보 평가 기록(관찰 전용)** — `CandidateEval`+`Engine.last_candidates`(캐릭터→시장
  파티션). 마감 평가(보유중/쿨다운/점수부족/게이트미충족)와 개장 체결(슬롯부족/현금부족/가격없음)
  단계별 차단 사유 7종, 통과 시 "예약". 기존 스킵 분기를 순서·조건 동일하게 분해 — 매매 결과
  불변은 기존 엔진·리플레이·동치성 테스트 전체의 무수정 통과로 증명(테스트 순수 추가만).
- **SignalStatusRow 영속** — 후보(`kind=후보`)·보유(`kind=보유`) 마감 상태. 시드는 리플레이 마지막
  거래일, 라이브는 on_close 동일 트랜잭션에 그 시장 분만 교체(교차 시장 보존). 보유행:
  red_score·stop_px(=avg×(1+locked_stop_pct), check_stops 트리거가와 일치)·trail_px(도달 시만)·close.
  라이브에서 유니버스 이탈 보유종목은 직전 red_score 승계(무위험 오인 방지).
- **거래 복기 API** — `/trades` 페이지네이션(기본 20)+필터(기간·종목·매수/매도·결정유형), 응답
  `{items,total}`. `/lifecycles` 포지션 생애 그룹핑(수량 0→BUY 시작, 0 도달 SELL 종료, orphan SELL
  제외, 진행중 생애는 limit과 무관하게 항상 포함).
- **의사결정판 API** — `/candidates`(오늘의 후보), positions 리스크 확장 9필드(비중·진입사유·현재
  적신호·손절가·트레일가·거리%·잠재손실·매도대기·기준시각 — 파생값은 저장 마감가 기준, 전부
  nullable로 500 방지), `/api/dashboard`에 today_actions(대기주문+강제매도 경보)·risk(현금비중·
  총노출·**최대 보유 비중(종목 집중)**·일 손익) — 기존 소비처 비파손(추가 필드 방식).
- **프론트 의사결정판** — Main을 오늘의 행동 → 위험 스트립 → 캐릭터 카드 → 시장/최근체결 순으로

- **거래 복기 UI** — TradesTable 페이지네이션·필터·"포지션 생애" 토글(진입→부분→청산 묶음, 생애
